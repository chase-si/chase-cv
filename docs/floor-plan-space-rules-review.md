# /floor-plan 空间规则审查与统一

日期：2026-10-14。范围：默认家具目录及页面的空间判断、家具标记、移动端摘要和检查列表。

## 审查结论

“实体冲突 → 最低净距 → 推荐净距”的分级合理，适合辅助比较家具规格。原页面的问题是同时运行两套判断，且没有明确区分目标家具和全屋范围，因此同一布局可能出现“摆放合适”、红色感叹号和非零检查数。

| 检查项 | 判断 | 本次处理 |
| --- | --- | --- |
| 实体碰撞 | 家具与家具、实体墙的真实面积重叠应要求调整；仅接触边缘不应算碰撞 | 保留 10 mm² 的数值容差，复用空间评估结果 |
| 房间边界 | 应检查完整家具范围，不能仅检查中心或“有一个角在房间内” | 默认检查复用空间评估的完整角点检查，补充局部越界回归 |
| 方向净距 | 应随旋转改变；低于 minimum 与仅低于 recommended 必须区分 | 默认检查统一使用目录规格的最低、推荐净距，分别为 error、warning |
| 活动区相互覆盖 | 两件家具的活动区可以共享；不能据此认定实体冲突 | 保留只比较活动区与实体障碍物的规则 |
| 普通窄缝 | 任意两件家具之间或家具与墙之间的小缝，不足以证明它是通道 | 默认检查移除通用“距离小于 600 mm 就是窄通道”的启发式，使用各侧净距 |
| 门口活动区 | 有助于发现可能阻碍开门、接近门口的家具，但当前缺少真实铰链和开启方向 | 保留现有门口推断作为 warning，纳入同一状态汇总 |
| 问题归属 | 某件家具侵犯另一件的使用空间，不代表两件的自身净距都失败 | `affectedFurnitureIds` 表示失败主体；`relatedEntityIds` 继续保留障碍物用于定位。实体重叠同时归属双方 |
| 重复计数 | 家具重叠是对称的，但全屋列表不应重复列两次 | 同一对家具重叠计 1 项，两件家具都有标记；不同侧、不同障碍的净距问题分别计数 |
| 未标定 | 不应声称最低或推荐毫米净距通过 | 两个入口都抑制净距结论；状态为 unavailable，空列表也不显示“全部通过” |
| 穿入深度 | 包含关系下，交集宽度并非脱离碰撞需要的距离 | 修正 SAT 分离深度，避免薄墙完全穿过家具时低估移动距离 |

## 页面统一规则

默认 `evaluatePlanRules(plan)` 先进行一次全量 `assessPlacementScenario`，把结构化发现转换为检查项，再补充门口活动区提醒。`assessmentFromRuleResults` 从同一列表派生全屋和单件状态。摘要、感叹号和检查列表不再独立计算或解释严重级别。

| 优先级 | 条件 | 文案与标记 |
| --- | --- | --- |
| 1 | 无可靠毫米比例 | 无法评估，不把未知显示为通过 |
| 2 | 实体碰撞、越界，或低于最低净距 | 需要调整，红色 |
| 3 | 仅低于推荐净距，或存在推定门口活动区提醒 | 空间略紧，黄色 |
| 4 | 当前配置未发现问题 | 摆放合适，无感叹号 |

- 选中家具时，移动端摘要明确显示“本件”；未选家具时显示“全屋”。选中正常家具后，全屋仍可能有其他问题，这是范围差异。
- “检查 N”始终指全屋列表的问题条数，不是失败家具数量；0 也明确显示。
- 检查面板只展示一份全屋列表，避免再叠加一份目标家具问题列表造成重复。
- 中英文状态文案共用 `getAssessmentStatusLabel`。检查详情从 `assessmentFinding` 生成方向、实测、最低和推荐值，不再把穿入深度误标为面积。
- 明确传入 `SpaceRuleConfig` 的旧自定义规则 API 保留原有阈值与配置语义；产品页没有使用该入口。

## 仍需理解的模型边界

这些是当前数据与产品模型的限制，不应通过增加更多强制报警来掩盖：

1. **净距是产品预设。** 目录中的 minimum / recommended 不是法规认证值。床两侧、柜门、座椅等需求会随使用方式变化，本次没有擅自改动目录阈值。
2. **门的开启侧是推定。** 现有规则根据房间关系推断，缺少铰链、内外开及扇数；不宜升级为“必然不能开门”。阳台、推拉门及普通通洞的接近路径仍不完整。
3. **没有完整动线求解。** 去掉任意窄缝报警可以减少误报，但也不意味着已验证从入口到各家具的路径连通性。应通过明确通道或路径模型单独扩展。
4. **二维占地假设。** 不区分高度，不能正确表达椅子收进桌下、悬挂家具等允许投影重叠的关系。
5. **不校验窗扇开启、采光和高度冲突。** 通过文案已收敛为“已配置的检查未发现问题”，不再笼统声称门窗规范全部通过。
6. **复杂边界仍需进一步建模。** 家具角点包含检查不是通用的凹多边形包含证明；通常实体墙碰撞可补充发现穿越凹口的情况，但不能宣称支持任意复杂房间几何。跨开放功能区的家具目前仍受“完整落在单一房间”约束。
7. **移动距离是局部修复提示。** 修正分离深度后，仍不能保证一次移动就同时解决所有方向及其他障碍物的问题；需移动后重新检查。

## 验证

- 复现原始问题：第一件家具正常，另一件在房间外；原摘要显示“摆放合适”，同时有感叹号和“检查 1”。回归覆盖全屋摘要、选中不同家具、检查列表及删除后的同步更新。
- 规则回归覆盖最低/推荐边界、允许靠墙的家具、重叠去重及双方归属、单方向净距的主体归属、门口提醒汇总、未标定抑制、局部越界，以及包含关系的分离深度。
- UI 回归覆盖黄色推荐净距标记、实测与最低/推荐值一致、未知比例时不显示通过。
- 在 HEAD 独立副本确认已有 6 个失败测试，均涉及旧沙发规格期望；没有在本次规则调整中修改这些无关规格。全项目 TypeScript 检查也存在其他功能测试文件的既有错误。
