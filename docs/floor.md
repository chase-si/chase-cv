# 户型家具规格验证 MVP

> 状态：当前产品方向，2026-09-21

## 1. 产品目标

用户从预设户型和通用家具规格中选择，在户型内摆放多件家具，并通过实体冲突与方向净距判断某个规格是否适合购买。

MVP 不尝试成为装修设计软件、CAD、自动布局工具或建筑规范审查工具。它只回答一个问题：

> 在当前户型和已有家具摆放下，这个通用家具规格是否放得下，使用空间是否合理？

## 2. 核心用户流程

```text
选择标准户型
  ↓
添加通用家具规格
  ↓
移动或旋转家具
  ↓
切换同一家具的预设规格
  ↓
查看当前目标家具的空间评估
```

一个方案可以包含多件家具。空间评估检查全部家具，但界面重点解释当前选中的目标家具。

## 3. MVP 范围

### 3.1 标准户型

- 从内置目录选择经过人工审核的标准户型。
- 使用毫米作为真实世界单位。
- 渲染墙体、房间、门窗和尺寸。
- MVP 中用户不能修改墙体、门窗、房间长宽或户型总长宽。

### 3.2 通用家具规格

- 家具由项目维护者预先提供，不接入品牌、商品、价格或 SKU。
- 一个家具定义包含多个预设规格，例如双人床的 `1500 × 2000 mm` 与 `1800 × 2000 mm`。
- 用户只能切换预设规格，不能任意输入长宽。
- 每个规格包含实体占地、朝向，以及前后左右四个方向的最低净距和推荐净距。

### 3.3 家具摆放

- 添加多件家具。
- 移动家具。
- 以 90° 步进旋转家具。
- 切换同一家具定义下的预设规格。
- 删除家具。

切换规格时保持家具中心点和旋转角度不变；用户可以在评估后继续调整位置。

### 3.4 空间评估

空间评估包含两个层级。

#### 实体冲突

以下情况必须调整：

- 家具实体之间重叠；
- 家具实体与墙体重叠；
- 家具实体超出房间边界。

#### 方向净距

家具规格的方向净距随家具一起旋转。每个方向包含两个阈值：

- 实际净距大于或等于推荐值：适合；
- 实际净距大于或等于最低值、但小于推荐值：需权衡；
- 实际净距小于最低值：必须调整。

净距区域只与墙体、房间边界和其他家具的实体占地比较。不同家具的净距区域不互相比较。MVP 不处理沙发与茶几、餐桌与餐椅等组合豁免。

### 3.5 评估状态

| 状态 | 含义 |
|---|---|
| 适合 | 无实体冲突，并满足全部推荐净距 |
| 需权衡 | 无实体冲突，但至少一个方向低于推荐净距且不低于最低净距 |
| 必须调整 | 存在实体冲突，或至少一个方向低于最低净距 |
| 无法判断 | 户型缺少可靠真实尺寸，无法计算毫米净距 |

“修复”不是状态。界面可以根据确定性结果给出简单建议，例如换小一档、移动或旋转家具，但不做自动布局。

## 4. 开发期资产预览

项目维护者需要快速验证新户型和家具数据。开发环境提供一个轻量资产预览页，不建设数据库、审批流或持久化后台。

### 4.1 户型预览流程

```text
粘贴或导入候选数据
  ↓
基础数据验证
  ↓
渲染预览
  ↓
人工检查并修改
  ↓
复制最终类 JSON 到代码
```

代码自动验证：

- 数据可以解析；
- 必填字段和类型正确；
- ID 唯一；
- 墙体、房间和门窗引用存在；
- 坐标为有限数值；
- 墙体不是零长度；
- 门窗宽度能够放入绑定墙体；
- 房间边界能够形成闭合区域。

人工看图判断：

- 内墙是否错误放置窗户；
- 门的位置是否符合房间用途；
- 厨房与卫生间等空间关系是否合理；
- 房间名称与用途是否正确；
- 动线是否符合真实生活；
- 重绘结果是否忠实于参考户型。

机器只为确定性数据错误提供修复建议。语义问题由维护者观察渲染结果并手工修改，不建立自动语义规则。

### 4.2 家具预览流程

- 粘贴或导入家具定义；
- 验证规格 ID、尺寸和净距数值；
- 切换规格并预览实体占地与方向净距区域；
- 旋转预览，确认前后左右方向正确；
- 复制最终类 JSON 到代码。

## 5. Module 方向

### 5.1 预设资产 Module

负责标准户型、家具定义、家具规格和基础数据验证。开发期资产预览页通过该 Module 加载候选数据；正式产品通过同一 Module 加载内置数据。

### 5.2 家具摆放 Module

负责在标准户型中添加、移动、旋转、切换规格和删除家具。MVP 不提供任意尺寸修改。

### 5.3 空间评估 Module

负责实体冲突和方向净距，并输出结构化评估结果。碰撞、越界和各方向净距是内部规则，不建立独立插件 Seam。

### 5.4 渲染 Adapter

负责显示标准户型、家具实体、净距区域和评估标记。渲染不得修改、重排或暗中修复输入数据。

## 6. 明确不做

- CubiCasa 或其他图片识别；
- 用户上传户型图片；
- 自动生成或自动修复户型；
- 用户编辑墙体、门窗、房间长宽或户型总长宽；
- 任意输入家具长宽；
- 品牌、价格、商品链接或 SKU；
- 家具组合关系和组合豁免；
- 全屋通行路径搜索；
- 自动布局；
- 建筑规范或无障碍合规判断；
- 通用规则插件系统；
- 资产数据库、审批流或运营后台。

## 7. 后续能力

只有 MVP 的预设资产、家具摆放和空间评估稳定后，才考虑：

1. 用户微调家具或户型尺寸；
2. 保存和恢复多个摆放方案；
3. 更细的门口避让规则；
4. 家具组合关系；
5. 图片识别或其他数据导入方式。

后续能力不得预先扩大 MVP 的 Interface。

## 8. 验收标准

### 8.1 预设资产

- 候选户型基础错误能阻止渲染并指出字段或对象；
- 合规户型能稳定渲染，且渲染不修正原始拓扑；
- 新家具只需增加家具定义和规格数据，不需要修改空间评估 Implementation；
- 家具预览能显示实体占地和旋转后的方向净距。

### 8.2 用户流程

- 用户可以选择标准户型；
- 用户可以添加多件家具并选择预设规格；
- 用户可以移动、旋转、切换规格和删除家具；
- 切换规格后立即重新评估；
- 当前目标家具得到适合、需权衡、必须调整或无法判断之一；
- 评估结果能指出相关家具或方向及实测净距。

### 8.3 可靠性

- 相同输入始终产生相同结果；
- 空间评估不依赖大模型；
- 标准户型和家具目录在构建或测试阶段统一验证；
- 无效数据不会覆盖或污染已验证资产。

## 9. Issue 拆分建议

先在现有已提交代码上删除已明确不属于 MVP 的能力，再开始新契约迁移。不要在保留识图、校准、自由缩放和高级拓扑编辑的工作区上继续开发。

1. 删除识图、校准和 source-import 能力；
2. 删除高级拓扑编辑、任意尺寸输入、草稿恢复和四阶段工作流；
3. 收敛领域类型与预设家具规格契约；
4. 建立候选户型和家具的基础验证；
5. 将开发期 lab 改为资产预览页；
6. 将家具操作迁移为预设规格切换；
7. 收敛实体冲突与方向净距为统一空间评估；
8. 简化用户流程为选择户型、摆放家具、查看评估；
9. 删除迁移期兼容 Adapter、旧数据形状及失效测试与文档；
10. 完成端到端验收。
